# Изменения

## 1.0.1 — 2026-09-29

Исправления по ретроспективной панели из пяти проверяющих (документация,
инженер, QA, безопасность, CTO) — правила ревью теперь в
`docs/agent-rules.md`.

Безопасность:

* SSRF через адрес записи: приватные адреса при скачивании — только для
  хоста портала, редиректы проходятся вручную с проверкой каждого шага;
  транспорт больше не ходит по редиректам сам (ни колбэк, ни провайдер);
* задание без `hash` отклоняется (400 `no_hash`): без него не работала
  защита от повторов;
* ротация токена эндпоинта — кнопкой на странице расхода и
  `ROTATE_TOKEN=1 cli/setup.php`; движки не перерегистрировались — токен
  остаётся прежним;
* эндпоинт не создаёт сессию на каждый запрос ядра.

Надёжность:

* любой сбой диспетчера (база, журнал, квота) отдаёт ядру ошибку
  `internal_error`, а не оставляет задание висеть до ttl; сбой записи
  расхода не съедает колбэк с оплаченным результатом;
* колбэк повторяется при недоступности портала (нет соединения, 429, 5xx);
* запись «в работе», брошенная умершим процессом, перехватывается повтором
  задания; сбой вставки в журнал больше не выглядит как «дубликат»;
* скачанная запись с ошибкой транспорта или длиннее 25 МБ не уходит на
  распознавание обрезком;
* агент: сбой эскалации не обрывает прогон и не оставляет сделку без
  отметки; три ошибки провайдера подряд (нет связи, лимит частоты, ключ)
  останавливают прогон, и сделки не помечаются проверенными; сделка, на
  которой падает сама модель, помечается проверенной с ошибкой, а не
  оплачивается каждый прогон; ручной прогон — под той же блокировкой;
* схема ответа анализа сделок — без ключевых слов, которые строгий режим
  structured outputs не принимает;
* откаты по стадиям не считают стадии чужого направления.

Обновление кита (2026-09-29) — новые опоры на ядро:

* движок, выбранный в настройках ИИ: CRM берёт его строго по коду, без
  фолбэка. Выбрать движки модуля — ссылка «Выбрать движок модуля» на
  странице настроек модуля (решение владельца: настройки ИИ портала модуль
  меняет только оттуда); заменяет и прежний выбор, но только
  зарегистрированными движками и audio — только вместе с text. Установщик
  туда не пишет, «Проверить и включить» выбор только показывает
  (`selected *` в отчёте). При удалении модуля наш код снимается с настройки: выбирал
  модуль — возвращается прежний движок, иначе — пусто;
* `audio` без `text` невидим CRM (`ThirdParty::hasQuality()`): отчёт не
  считает audio готовым, если text не зарегистрировался;
* `cli/core-api-guard.php` — версия кита: видимость движка с тем же фильтром
  качества, что в CRM, и выбранный движок;
* документация: гейты 10–13 (выбор по коду, audio требует text, права
  ответственного на дело звонка, одно задание распознавания на дело).

Решения владельца (2026-10-02):

* установка и включение раздельны: установщик только создаёт таблицы,
  заглушки и токен (`Setup::prepare()`); обход BaaS, движки и агент — по
  кнопке «Проверить и включить» (`Setup::run()`). Пометку «обход BaaS
  включил модуль» теперь ставит сам `Setup`, а не установщик: раньше при
  включении кнопкой удаление его бы не сняло. Порталы 1.0.0, где обход
  включали кнопкой, пометки задним числом не получают — удаление оставит
  обход включённым, снять руками: `BaasManager::setIgnored(false)`;
* удаление с `savedata = Y` снимает и пометку `SYS_baasset`: иначе после
  переустановки модуль снял бы обход, включённый уже не им.

Приёмка на коробке 2026-10-02 (bx-shef/toolsai#3, main 26.750, ai 26.1100,
crm 26.800):

* дело старшему при анализе сделки не ставилось: в crm 26.800 конструктор
  `Activity\Entity\ToDo` требует провайдер вторым аргументом —
  `ArgumentCountError`. Провайдер передаётся, если конструктор его ждёт;
* ядро ai ходит на адрес движка только по публичному IP
  (`setPrivateIp(false)` при регистрации и на каждое задание) —
  `01-engine-contract.md` утверждал обратное. Исправлено; «Проверить и
  включить» при отказе регистрации называет причину, если адрес
  резолвится в приватный IP; стенд в Docker — в подсети `198.18.0.0/24`;
* внешний адрес без схемы отчёт называл «не задан» — теперь «не разобран:
  нужен вид https://…»;
* «Выбрать движок модуля» открывалась в новой вкладке (BB `[URL]`), и
  исходная страница оставалась с «не выбран» — теперь обычная ссылка;
* гейт 8 (`AI_BOX_AGREEMENT`) на ai 26.1100 — всегда принят.
* анализ сделок без «старшего» — отчёт прогона пишет «старший не задан —
  дела нет», а не молчит;
* на месте заглушки эндпоинта чужой файл — движки не регистрируются: его
  ответ 200 прошёл бы проверку ядра, и задания ушли бы не туда;
* `docker/stand/test-call.sh` — уникальное имя записи.

Боевая проверка (bx-shef/toolsai#12):

* DeepSeek и другие провайдеры без `response_format: json_schema`:
  `completeJson()` после отказа 4xx повторяет запрос с `json_object` (схема —
  в системном сообщении) и сверяет ответ со схемой сам — анализ сделок на
  них работает; 401/403/429/5xx — без повтора; оплаченный, но негодный
  ответ (не JSON, не по схеме) пишется в журнал с ценой и идёт в квоту;
* настройка «Дополнительные параметры модели текста» (JSON в
  `/chat/completions` как есть) — например, выключить рассуждения DeepSeek,
  которые оплачиваются как выходные токены; модель, сообщения и формат
  ответа не перекрываются; `cli/preflight.php` показывает, применяются ли;
* выбор движков по категориям: «оба / только текст / только
  распознавание» — сценарий «текст модуля, распознавание штатное
  `BitrixAudio`» больше не требует правки настроек ИИ руками;
* адрес настроек ИИ в подсказках и документации — коробочный
  `/configs/?page=ai` (`/settings/configs/` — облачный, на коробке не
  открывается);
* отчёт о выборе движка (`selected …` в «Проверить и включить»,
  `cli/setup.php`, `cli/preflight.php`) называет движок модуля по имени и
  коду вместо «наш»; штатный движок в соседней категории — OK без совета
  заменить его; строки INFO — что выбрано в других сценариях CRM (оценка
  звонка по скрипту, повторные продажи, автоматические дела и антиспам),
  которые модуль не обслуживает;
* `cli/preflight.php` показывает строку из `/etc/hosts` для хоста внешнего
  адреса (BitrixVM пишет домен на локальный IP и может вернуть строку при
  перенастройке).

Установка Composer'ом — `docs/composer.md` (проверено установкой в пустой
каталог): `composer.json` вне корня сайта, `extra.bitrix-dir`, репозитории
GitHub до публикации на Packagist; промпт боевой проверки и runbook — на

Боевая проверка:

Перерегистрация движков (приёмка, 8.2–8.3) — штатно, в два шага (решение
владельца 2026-10-03: без обхода ядра):

* смена адреса: сначала проверка нового адреса тем же GET, что у ядра (не
  200 — движки не трогаем), потом снять все движки со старым адресом,
  потом регистрировать — валидатор ядра грузит список движков в процесс
  один раз (`Engine::loadThirdParty()`), и так он грузит его уже без них;
* список успели загрузить раньше в этом запросе — движок снят и
  регистрируется вторым нажатием «Проверить и включить», отчёт об этом
  говорит; ротация токена тогда новый токен оставляет;
* `Engine\Registrar`: `register()`, `getUrl()`, `probe()` вместо `ensure()`.

Открыто: текстовая цепочка без своих промптов (CLAUDE.md, «Известные

## 1.0.0 — 2026-09-28

Первый выпуск. База — кит `shef-toolsai-kit` (исследование ядра, контракт,
скелет модуля, диагностика), доведённый до рабочего модуля по канону
линейки shef.options.

* Движок Копилота: регистрация категорий `audio` и `text` через
  `\Bitrix\AI\ThirdParty\Manager::register()`, эндпоинт `GET 200` /
  `POST 202`, фоновая обработка, колбэк `{"result": [...]}`.
* Провайдеры: заглушка `echo` и OpenAI-совместимое API — распознавание
  (`/audio/transcriptions`, verbose_json) и чат (`/chat/completions`,
  JSON Schema).
* Учёт расхода: журнал `shef_toolsai_usage` с идемпотентностью по хэшу
  задания, месячная квота, страница «ИИ: расход и остаток».
* Анализ сделок: агент с фильтром до модели, вердикт по схеме, комментарий в
  таймлайн и дело старшему, таблица `shef_toolsai_deal_check`.
* Включение одной кнопкой и `cli/setup.php`: токен, заглушки, обход BaaS,
  движки, агент — идемпотентно, после каждого обновления платформы.
* Стенд в Docker, заглушка OpenAI-совместимого API и промпт приёмки для
  ИИ-агента.

Исправлено относительно кита:

* защита эндпоинта подписью `X-Shef-Signature` не работала бы никогда — ядро
  своих заголовков не шлёт; теперь токен в `completions_url`, колбэк — только
  на хост портала;
* классы лежали в `lib/` с заглавными буквами — на Linux ядро их не нашло бы;
* `docs/00-research.md` говорил «ядро ждёт 200» на POST — ждёт 202;
* проверка квоты пропускала перерасход (остаток 0 при `canSpend(0)`);
* ключ провайдера, повторённый в тексте его ошибки, уходил в журнал.
