# Промпт: боевая проверка shef.toolsai на рабочей коробке

Готовый промпт для ИИ-агента (Claude Code и подобные) с ssh на **рабочий**
портал Битрикс24 и для человека рядом с ним. Копируется в сессию **целиком,
от линии до конца файла**, вместе с клоном `bx-shef/toolsai`. Перед запуском
заполните блок «Вход».

Это не приёмка на стенде ([agent-docker-test.md](agent-docker-test.md)):
стенд уже пройден ([отчёт](reports/docker-2026-10-02.md)), здесь —
включение на живом портале **одним** настоящим звонком, без удаления модуля и
без экспериментов, которые портал может не пережить.

---

## Роль и цель

Ты — инженер внедрения модуля `shef.toolsai` на **рабочую коробку**
Битрикс24. Модуль даёт Копилоту свой ИИ-движок: запись звонка → текст в
карточке сделки или лида через выбранного провайдера, с учётом расхода и
месячной квотой.

Цель дня — **один настоящий звонок с записью распознан в карточке** на
OpenAI-совместимом провайдере, расход виден на странице «ИИ: расход и
остаток», и всё это обратимо. Не «кажется, работает», а доказательство на
каждом шаге: вывод команды, строка SQL, текст из карточки.

## Вход

Заполняет человек перед запуском:

| что | значение |
|---|---|
| ssh и корень сайта | `<user@host>`, `<DOCUMENT_ROOT, обычно /home/bitrix/www>` |
| Внешний адрес портала | `<https://crm.example.by>` |
| Провайдер распознавания | `<адрес API, ключ — передать отдельно, не в чат>`, модель `<whisper-1>` |
| Цена минуты распознавания | `<например 0.006>` в валюте квоты |
| Квота на месяц | `<например 20>` — для первого дня маленькая |
| Тестовая воронка | `<лиды / направление сделок N>` — **одна** |
| Тестовый звонок | `<кто звонит, на какой номер, кто ответственный>` |
| Версия модулей | `<main или тег>` |

## Правила (рабочий портал)

* **Ничего не удалять.** Ни модуль, ни таблицы, ни движки чужих модулей.
  Удаление модуля уносит журнал расхода — только по решению человека.
* **Без нужды не менять внешний адрес и не ротировать токен после
  регистрации движков.** Смена адреса идёт штатно в два шага: если отчёт
  пишет «снят со старого адреса… следующим нажатием» — «Проверить и
  включить» **ещё раз**, пока оба движка не `unchanged`; между нажатиями
  распознавание не идёт.
* **text — заглушка `echo`, пока не дошли до шага 7a.** Заглушка кладёт
  в карточку служебный текст `[заглушка shef.toolsai]` — на рабочей
  воронке не держать её дольше одного тестового звонка. Настоящий
  провайдер для текста — шаг 7a, со «Своими промптами» модуля: промпты
  Копилота на коробке обфусцированы, по ним модель отвечает «не понял,
  что нужно сделать» (bx-shef/toolsai#20).
* **Перед каждым изменением — записать, что было** (значение, вывод
  `preflight.php`). Всё, что меняешь, должно откатываться по разделу
  «Откат».
* Секреты (ключ API, токен эндпоинта, вебхуки) — только маской.
* Действие, которое не описано здесь и меняет портал, — сначала спросить
  человека.
* Нашёл дефект модуля — не чинить на портале: записать в отчёт с
  воспроизведением; правка — PR в `bx-shef/toolsai`.

## Как запускать скрипты

**От пользователя веб-сервера**, не от root: подключение ядра создаёт файлы
кеша, и созданные root'ом веб-сервер потом не перезапишет.

```bash
cd <корень>/bitrix/modules/shef.toolsai/cli && sudo -u bitrix env DOCUMENT_ROOT=<корень> php -f preflight.php
```

`<корень>` — из «Вход», `bitrix` — пользователь веб-сервера (BitrixVM). Ниже
`cd <корень>/bitrix/modules/shef.toolsai/cli && sudo -u bitrix env DOCUMENT_ROOT=<корень>`
сокращено до `BX`: **разворачивай полностью в каждой команде** —
оболочка агента не хранит переменные и алиасы между вызовами. Параметры
скрипта — после `env`: `sudo -u bitrix env DOCUMENT_ROOT=<корень> ACTIVITY_ID=123 php -f call-report.php`.

`preflight.php` и `call-report.php` только читают. `setup.php` и
`rollback.php` меняют портал — только на своих шагах.

Модуля ещё нет — то же после шага 1. Запиши в отчёт из `preflight.php`:

для отката (где ядро хранит этот выбор, зависит от версии `ai`), и

## Шаг 1. Модули

Файлы — **Composer'ом**, по [composer.md](composer.md): `composer.json`
вне корня сайта (BitrixVM — `/home/bitrix/composer.json`, `"bitrix-dir":
"www/bitrix"`), `bxshef/toolsai` `1.x-dev` из репозитория GitHub, запуск —
**от пользователя веб-сервера**:

```bash
cd /home/bitrix && sudo -u bitrix composer install --no-dev --no-interaction
ls /home/bitrix/www/bitrix/modules | grep shef   # options, problems, toolsai
```

Уже есть `composer.json` проекта — **не перезаписывать**: добавить в него
`repositories`, `require`, `allow-plugins`, `bitrix-dir` и показать дифф
человеку до `composer install`. В отчёт — `composer.lock`: какие коммиты
`bxshef/*` встали.

Затем **Настройки → Модули** — установить по порядку `shef.options` →
`shef.problems` → `shef.toolsai`. Уже стоят — только обновить файлы
(`composer update 'bxshef/*'`) и прогнать «Проверить и включить»
(установщик повторно не нужен).

**Ожидается:** отчёт установки — только ✔ `token` и обе `page …`. Портал
установка не меняет (решение владельца).

## Шаг 3. Настройки модуля

**Настройки → Настройки модулей → [SH] ИИ-инструменты:**

| вкладка | что |
|---|---|
| Движок | внешний адрес — **со схемой**; audio = «OpenAI-совместимое API»; text = «Заглушка» (до шага 7a); квота — из «Вход» |
| Провайдер | адрес API, ключ, модель распознавания, цена минуты |
| Анализ сделок | **выключен** (сегодня не проверяем) |

Затем:

```bash
BX php -f preflight.php
```

**Ожидается:** FAIL нет. Особо:
* `<хост> → IP с сервера` — публичный IP. Приватный — ядро ai не пойдёт на
  адрес движка; это вопрос DNS сервера (split-DNS, hosts), не модуля —
  **стоп, к человеку**. Строка `<хост> в /etc/hosts` — откуда приватный
  адрес (на BitrixVM — блок `ANSIBLE MANAGED BLOCK`, см.
  [01-engine-contract.md](01-engine-contract.md), «Требования к сети»);
* `GET эндпоинта, как ядро` — 200;
* `GET …/models` — 200. `нет ответа … TLS` — перехват TLS прокси или
  антивирусом (как на стенде): **стоп, к человеку**, проверку SSL не
  выключать.

## Шаг 4. Включение

1. **Сервисы → ИИ: расход и остаток → «Проверить и включить»** (или
   `BX php -f setup.php`). Ожидается: `engine audio`, `engine text` —
   `registered`; `crm::AI_IGNORE_BAAS` — Y; `agent` — есть; `selected …` —
   FAIL «не выбран»/«выбран «X»» — это нормально до п. 2.
   Повторный прогон — оба движка `unchanged`. Отчёт просит «следующим
   нажатием» — нажать ещё раз (см. «Правила»).
2. **Настройки модуля → Движок → «Выбрать движок модуля».** Ожидается:
   «Готово», оба `sheftoolsai_*`; в `/configs/?page=ai` — наши
   движки. Прежние значения модуль запомнил и вернёт при удалении; для
   отката без удаления — записанные на шаге 0.
3. `BX php -f preflight.php` — раздел 5 весь OK.

## Шаг 5. Время ответа эндпоинта

Главный неподтверждённый риск: на apache + mod_php (BitrixVM) нет
`fastcgi_finish_request()`. Если веб-сервер держит соединение до конца
обработки, ядро снимет задание по таймауту 5 секунд. Проверь, **чем**
обслуживается PHP (`php-fpm` или `mod_php`) и замерь POST **с сервера
портала**:

Токен — из базы, не через PHP (вывод ядра в stdout испортил бы значение):

```sql
SELECT VALUE FROM b_option WHERE MODULE_ID = 'shef.toolsai' AND NAME = 'SYS_token';
```

Всё ниже — **одной** командой (переменные между вызовами не живут):

```bash
TOKEN=<64 hex из запроса выше>
URL=<внешний адрес>
HASH=prodcheck$(date +%s)
curl -s -o /dev/null -w '%{http_code} %{time_total}\n' -X POST \
  "$URL/bitrix/tools/shef_toolsai_completions.php?token=$TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"category":"text","prompt":"ping","callbackUrl":"'$URL'/__nowhere?hash='$HASH'","errorCallbackUrl":"'$URL'/__nowhere?hash='$HASH'"}'
```

**Ожидается:** `202`. Токен в отчёт — маской. Колбэк уйдёт на
несуществующий адрес портала и получит 404 — это нормально; строка в журнале
— `text/echo/SUCCESS`.

**Время этого запроса риск не доказывает:** на заглушке обработка занимает
миллисекунды, а curl закрывает чтение, получив `Content-Length`. Настоящий
ответ — на шаге 7: время POST **ядра** к
`shef_toolsai_completions.php` в access-логе веб-сервера (`$request_time` у
nginx, `%D` у apache) при звонке на настоящем провайдере — должно быть < 1 с,
а задание в `call-report.php` — не упасть по таймауту.

## Шаг 7. Один настоящий звонок

Человек делает звонок из «Вход»: **на лид или сделку** тестовой воронки
(не на контакт), запись 10 с…60 мин, ответственный имеет право **изменять**
дело звонка. Каждый повтор — новый звонок (одно задание на дело, гейт 13).

Через 1–3 минуты:

```bash
BX php -f call-report.php
BX ACTIVITY_ID=<id дела звонка> php -f call-report.php
BX ACTIVITY_ID=<id дела звонка> php -f ai-call-autostart-diag.php
grep shef_toolsai_completions <access-лог веб-сервера> | tail -5   # время POST ядра (шаг 5)
```

**Ожидается:**
* в карточке — текст расшифровки настоящего разговора;
* журнал: `audio/openai/SUCCESS`, секунды ≈ длительности, стоимость = цена
  × минуты; затем `text/echo/SUCCESS` (резюме-заглушка, первый звонок);
* «ИИ: расход и остаток» — то же.

Не дошло до модуля (журнал пуст) — `ai-call-autostart-diag.php` покажет
гейт. Дошло, но `ERROR` — текст ошибки из журнала и лога shef.problems.

## Шаг 7a. Текст на настоящей LLM

Модуль на 1.0.2 и новее (раньше модели уходил сырой шаблон промпта —
bx-shef/toolsai#11). Записать, что стоит в «резюме и заполнение полей» в
`/configs/?page=ai` (для отката).

1. Вкладка «Движок»: «Текст» = «OpenAI-совместимое API»; вкладка
   «Провайдер»: модель текста, цены за миллион токенов; «Свои промпты» —
   **включено**. Промпты Копилота закрыты метками уже в дистрибутиве
   (`ai/install/prompts/world.json`, 84 из 121, раскрываются только в
   облаке): по промпту ядра модель получает текст звонка без инструкции
   (bx-shef/toolsai#20). Оценка звонка по скрипту — тоже через модуль, если
   в `/configs/?page=ai` для неё выбран «Shef ToolsAI — текст».
2. Новый звонок (как в шаге 7). Ожидается:
   * журнал: две строки `text/openai/SUCCESS` — резюме и поля, токены и
     цена в ожидаемых пределах;
   * `BX ACTIVITY_ID=<id> php -f call-report.php`: в `b_crm_ai_queue`
     Summarize и FillFields — без `ERROR`, у FillFields нет
     `PAYLOAD_IS_EMPTY`, дальше по цепочке появились ScoreCall (на нашем
     движке — оценка по критериям скрипта) и AnalyzeCommunication (если
     включены);
   * в карточке: резюме по делу; поля заполнены именно полями (а не всё в
     комментарий), значения не выдуманы.
3. Не годится — быстрый откат только текста (ниже) и находку в issue:
   что в карточке, что в журнале и в `b_crm_ai_queue`.

## Шаг 8. Оставить или откатить

Решает человек. **Оставить** — квоту и воронки расширять по
`docs/04-runbook.md`, шаг 8 (наблюдение первую неделю).

### Откат только текста

Плохие резюме или поля, распознавание при этом в порядке: в
`/configs/?page=ai` вернуть «резюме и заполнение полей» на прежний движок
(записан в шаге 7a; на облачной связке обычно `b24ai`), «расшифровку
звонков» не трогать. Одно действие, модуль и движки остаются;
`rollback.php` для этого избыточен — он снимает оба движка и обход BaaS.

### Откат (без удаления модуля, журнал расхода цел)

1. Автозапуск в тестовой воронке — выключить распознавание (руками).
2. План отката и сам откат:

   ```bash
   BX php -f rollback.php                                                       # план, ничего не меняет
   BX CONFIRM=1 php -f rollback.php   # выполнить
   ```

   Возвращает выбор в настройках ИИ (что стояло до «Выбрать движок
   модуля»), снимает наши движки и агент анализа сделок, выключает обход
   BaaS — только если включал его модуль.
3. `BX php -f preflight.php` — сверить с `/tmp/toolsai-before.txt`; выбор в
   настройках ИИ не совпал с шагом 0 — вернуть руками в
   `/configs/?page=ai`.

Полное удаление модуля — только по решению человека: уносит журнал расхода
(с `savedata = Y` — оставляет, `docs/04-runbook.md`, «Откат»).
