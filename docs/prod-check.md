# Промпт: боевая проверка shef.toolsai на рабочей коробке

Готовый промпт для ИИ-агента (Claude Code и подобные) с ssh на **рабочий**
портал Битрикс24 и для человека рядом с ним. Копируется в сессию **целиком,
от линии до конца файла**, вместе с клоном `bx-shef/toolsai`. Перед запуском
заполните блок «Вход».

Это не приёмка на стенде ([agent-docker-test.md](agent-docker-test.md)):
стенд уже пройден ([отчёт](reports/docker-2026-10-02.md)), здесь —
включение на живом портале **одним** настоящим звонком, без удаления модуля и
без экспериментов, которые портал может не пережить.

---

## Роль и цель

Ты — инженер внедрения модуля `shef.toolsai` на **рабочую коробку**
Битрикс24. Модуль даёт Копилоту свой ИИ-движок: запись звонка → текст в
карточке сделки или лида через выбранного провайдера, с учётом расхода и
месячной квотой.

Цель дня — **один настоящий звонок с записью распознан в карточке** на
OpenAI-совместимом провайдере, расход виден на странице «ИИ: расход и
остаток», и всё это обратимо. Не «кажется, работает», а доказательство на
каждом шаге: вывод команды, строка SQL, текст из карточки.

## Вход

Заполняет человек перед запуском:

| что | значение |
|---|---|
| ssh и корень сайта | `<user@host>`, `<DOCUMENT_ROOT, обычно /home/bitrix/www>` |
| Внешний адрес портала | `<https://crm.example.by>` |
| Провайдер распознавания | `<адрес API, ключ — передать отдельно, не в чат>`, модель `<whisper-1>` |
| Цена минуты распознавания | `<например 0.006>` в валюте квоты |
| Квота на месяц | `<например 20>` — для первого дня маленькая |
| Тестовая воронка | `<лиды / направление сделок N>` — **одна** |
| Тестовый звонок | `<кто звонит, на какой номер, кто ответственный>` |
| Версия модулей | `<main или тег>` |

## Правила (рабочий портал)

* **Ничего не удалять.** Ни модуль, ни таблицы, ни движки чужих модулей.
  Удаление модуля уносит журнал расхода — только по решению человека.
* **Не менять внешний адрес и не ротировать токен после регистрации
  движков.** Известный дефект (bx-shef/toolsai#3, 8.2–8.3): перерегистрация
  обоих движков в одном запуске снимает text-движок, а без него CRM не видит
  и audio. Если пришлось — «Проверить и включить» **ещё раз** и убедиться,
  что оба движка `unchanged`.
* **text-провайдер — заглушка `echo`.** Промпты Копилота на коробке
  обфусцированы; свои промпты модуля ещё не готовы (решение владельца —
  писать свои). На реальной LLM резюме и заполнение полей будут мусором и
  стоят денег. Распознавание (`audio`) — на настоящем провайдере.
* **Перед каждым изменением — записать, что было** (значение, вывод
  `preflight.php`). Всё, что меняешь, должно откатываться по разделу
  «Откат».
* Секреты (ключ API, токен эндпоинта, вебхуки) — только маской.
* Действие, которое не описано здесь и меняет портал, — сначала спросить
  человека.
* Нашёл дефект модуля — не чинить на портале: записать в отчёт с
  воспроизведением; правка — PR в `bx-shef/toolsai`.

## Шаг 0. Снимок «как было»

```bash
cd $DOCUMENT_ROOT/bitrix/modules/shef.toolsai/cli   # если модуль уже стоит
php -f preflight.php       | tee /tmp/toolsai-before.txt
php -f core-api-guard.php  | tee /tmp/toolsai-guard-before.txt
php -f ai-call-autostart-diag.php | tee /tmp/toolsai-diag-before.txt
```

Модуля ещё нет — то же после шага 1. Запиши в отчёт из `preflight.php`:
версии, «выбран в настройках ИИ» для audio и text (**это значения для
отката**), `crm::AI_IGNORE_BAAS`. Плюс резервная копия БД средствами
хостинга или хотя бы `b_option` по модулям `ai` и `crm`:

```sql
SELECT MODULE_ID, NAME, VALUE FROM b_option
 WHERE MODULE_ID IN ('ai','crm') AND (NAME LIKE '%engine%' OR NAME LIKE '%BAAS%' OR NAME LIKE 'ai_autostart%');
```

## Шаг 1. Модули

`shef.options` 3.0+, `shef.problems` 2.0+, `shef.toolsai` из `main` (или
тега). Архивы — `./build.sh` в каждом репозитории, распаковать в
`bitrix/modules/`, поставить в **Настройки → Модули** по порядку. Уже стоят
— обновить файлы и прогнать «Проверить и включить» (установщик повторно не
нужен).

**Ожидается:** отчёт установки — только ✔ `token` и обе `page …`. Портал
установка не меняет (решение владельца).

## Шаг 2. Лог CRM

`docs/04-runbook.md`, шаг 1: логгер `crm.Integration.AI` в
`/bitrix/.settings_extra.php`, файл вне корня сайта. Без него отказ
автозапуска не виден.

## Шаг 3. Настройки модуля

**Настройки → Настройки модулей → [SH] ИИ-инструменты:**

| вкладка | что |
|---|---|
| Движок | внешний адрес — **со схемой**; audio = «OpenAI-совместимое API»; text = «Заглушка»; квота — из «Вход» |
| Провайдер | адрес API, ключ, модель распознавания, цена минуты |
| Анализ сделок | **выключен** (сегодня не проверяем) |

Затем:

```bash
php -f preflight.php
```

**Ожидается:** FAIL нет. Особо:
* `<хост> → IP с сервера` — публичный IP. Приватный — ядро ai не пойдёт на
  адрес движка; это вопрос DNS сервера (split-DNS, hosts), не модуля —
  **стоп, к человеку**;
* `GET эндпоинта, как ядро` — 200;
* `GET …/models` — 200. `нет ответа … TLS` — перехват TLS прокси или
  антивирусом (как на стенде): **стоп, к человеку**, проверку SSL не
  выключать.

## Шаг 4. Включение

1. **Сервисы → ИИ: расход и остаток → «Проверить и включить»** (или
   `php -f setup.php`). Ожидается: `engine audio`, `engine text` —
   `registered`; `crm::AI_IGNORE_BAAS` — Y; `agent` — есть; `selected …` —
   FAIL «не выбран»/«выбран «X»» — это нормально до п. 2.
   Повторный прогон — оба движка `unchanged`. Если text — «Запись с таким
   code уже существует»: прогнать ещё раз (дефект, см. «Правила»).
2. **Настройки модуля → Движок → «Выбрать движок модуля».** Ожидается:
   «Готово», оба `sheftoolsai_*`; в `/settings/configs/?page=ai` — наши
   движки. Прежние значения модуль запомнил и вернёт при удалении; для
   отката без удаления — записанные на шаге 0.
3. `php -f preflight.php` — раздел 5 весь OK.

## Шаг 5. Время ответа эндпоинта

Главный неподтверждённый риск: на apache + mod_php (BitrixVM) нет
`fastcgi_finish_request()`. Если веб-сервер держит соединение до конца
обработки, ядро снимет задание по таймауту 5 секунд. Проверь, **чем**
обслуживается PHP (`php-fpm` или `mod_php`) и замерь POST **с сервера
портала**:

```bash
TOKEN=$(php -r '$_SERVER["DOCUMENT_ROOT"]="'$DOCUMENT_ROOT'"; require "'$DOCUMENT_ROOT'/bitrix/modules/main/include/prolog_before.php"; echo \Bitrix\Main\Config\Option::get("shef.toolsai","SYS_token");')
curl -s -o /dev/null -w '%{http_code} %{time_total}\n' -X POST \
  "<внешний адрес>/bitrix/tools/shef_toolsai_completions.php?token=$TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"category":"text","prompt":"ping","callbackUrl":"<внешний адрес>/__nowhere?hash=prodcheck'$(date +%s)'"}'
```

**Ожидается:** `202` и время < 1 с. Токен в отчёт — маской. Колбэк уйдёт на
несуществующий адрес портала и получит 404 — это нормально; строка в журнале
— `text/echo`.

## Шаг 6. Автозапуск в тестовой воронке

`docs/04-runbook.md`, шаг 4: карточка → настройки Копилота → автозапуск —
**только тестовая воронка** из «Вход»; операция «распознавание записи»
включена; направления — какие нужны. Сохранить явно.

```bash
php -f ai-call-autostart-diag.php   # раздел 3: у тестовой воронки «есть Transcribe?» = OK
```

## Шаг 7. Один настоящий звонок

Человек делает звонок из «Вход»: **на лид или сделку** тестовой воронки
(не на контакт), запись 10 с…60 мин, ответственный имеет право **изменять**
дело звонка. Каждый повтор — новый звонок (одно задание на дело, гейт 13).

Через 1–3 минуты:

```bash
php -f call-report.php
ACTIVITY_ID=<id дела звонка> php -f call-report.php
ACTIVITY_ID=<id дела звонка> php -f ai-call-autostart-diag.php
```

**Ожидается:**
* в карточке — текст расшифровки настоящего разговора;
* журнал: `audio/openai/SUCCESS`, секунды ≈ длительности, стоимость = цена
  × минуты; затем `text/echo/SUCCESS` (резюме-заглушка);
* «ИИ: расход и остаток» — то же.

Не дошло до модуля (журнал пуст) — `ai-call-autostart-diag.php` покажет
гейт. Дошло, но `ERROR` — текст ошибки из журнала и лога shef.problems.

## Шаг 8. Оставить или откатить

Решает человек. **Оставить** — квоту и воронки расширять по
`docs/04-runbook.md`, шаг 8 (наблюдение первую неделю).

### Откат (без удаления модуля, журнал расхода цел)

1. Автозапуск в тестовой воронке — выключить распознавание.
2. `/settings/configs/?page=ai` — вернуть движки, записанные на шаге 0.
3. Снять наши движки:

   ```bash
   php -r '$_SERVER["DOCUMENT_ROOT"]="'$DOCUMENT_ROOT'"; require "'$DOCUMENT_ROOT'/bitrix/modules/main/include/prolog_before.php";
   \Bitrix\Main\Loader::includeModule("shef.toolsai");
   (new \Shef\ToolsAi\Engine\Registrar())->unregister("audio");
   (new \Shef\ToolsAi\Engine\Registrar())->unregister("text");'
   ```
4. Обход BaaS — вернуть, только если до нас был N:
   `\Bitrix\Crm\Integration\AI\BaasManager::setIgnored(false);`
5. `php -f preflight.php` — сверить с `/tmp/toolsai-before.txt`.

Полное удаление модуля — только по решению человека: уносит журнал расхода
(с `savedata = Y` — оставляет, `docs/04-runbook.md`, «Откат»).
