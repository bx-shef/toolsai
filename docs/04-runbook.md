# Runbook: как включить на коробке

По шагам, в этом порядке. Каждый шаг проверяемый — не переходи дальше, пока
текущий не даёт ожидаемого результата. Пути ниже — для BitrixVM
(`/home/bitrix/www`); модуль стоит в `bitrix/modules/shef.toolsai`
(или `local/modules/shef.toolsai` — работает и там).

---

## Шаг 0. Разведка (до включения)

```bash
cd /home/bitrix/www/bitrix/modules/shef.toolsai/cli
/usr/bin/php -f ai-call-autostart-diag.php
/usr/bin/php -f ai-limits-report.php
/usr/bin/php -f core-api-guard.php
```

`cli/` едет вместе с модулем; если модуль ещё не поставлен — возьми каталог
из архива и укажи корень явно: `DOCUMENT_ROOT=/home/bitrix/www php -f …`.

Выпиши себе три вещи:

| Что | Где смотреть | Зачем |
|---|---|---|
| зона лицензии | первая строка диагностики | не `ru` -> в дефолте автозапуска нет `Transcribe` |
| модуль `bitrix24` | отчёт по лимитам | есть -> включится промо-лимит 5/сутки |
| `ai::public_url` | сторож, раздел «Настройки» | от него зависят колбэк И загрузка записи |

## Шаг 1. Включить лог (первым делом)

Без него все отказы автозапуска уходят в `NullLogger`
(`crm/lib/Service/Logger/LoggerFactory.php:22-24`) и отлаживать придётся вслепую.

В `/home/bitrix/www/bitrix/.settings_extra.php`:

```php
<?php
return [
	'loggers' => [
		'value' => [
			'crm.Integration.AI' => [
				'className' => '\\Bitrix\\Main\\Diag\\FileLogger',
				'constructorParams' => ['/home/bitrix/sh_log/crm-ai.log'],
				'level' => \Psr\Log\LogLevel::DEBUG,
			],
		],
		'readonly' => false,
	],
];
```

Лог — вне корня сайта, как у shef.problems: каталог `/home/bitrix/sh_log`
веб-сервер не отдаёт. Он должен существовать и быть доступен на запись.

**Проверка:** тестовый звонок — в логе строки от `AutoLauncher`.

## Шаг 2. Модуль

Нужны `shef.options` 3.0.0+ и `shef.problems` 2.0.0+ — установщик проверит
и откажется ставиться без них.

1. Распаковать `shef.toolsai.zip` в `bitrix/modules/` (или `composer require
   bxshef/toolsai`).
2. Поставить: **Настройки → Модули → [SH] ИИ-инструменты → Установить**.
   Установщик создаст таблицы, запишет заглушки эндпоинта и страницы
   расхода, сгенерирует токен, включит обход BaaS и зарегистрирует агент.
   Движки на чистой установке обычно **не** регистрируются — внешний адрес
   ещё не задан, и отчёт на экране установки это говорит.

**Проверка:** в отчёте установки `token`, обе `page …`,
`crm::AI_IGNORE_BAAS` и `agent` — ✔; `engine *` — ✖ «не задан внешний адрес».

## Шаг 3. Внешний адрес и движки

1. **Настройки модуля → Движок → «Внешний адрес портала»**: адрес, по
   которому портал доступен **с самого себя и снаружи**, например
   `https://crm.example.by`. Пусто — берётся `ai::public_url`.
2. **Сервисы → ИИ: расход и остаток → «Проверить и включить»** (или
   `php -f cli/setup.php`, можно сразу с `PUBLIC_URL=https://crm.example.by`).

Регистрация движка делает GET на эндпоинт и требует ровно 200. Проверить
руками:

```bash
curl -i https://crm.example.by/bitrix/tools/shef_toolsai_completions.php
# HTTP/1.1 200 и {"status":"ok"}
```

Токен эндпоинта едет в адресе и попадает в access-лог веб-сервера. Не
логируйте query-строку для `/bitrix/tools/shef_toolsai_completions.php`
(в nginx — отдельный `location` с `access_log off` или свой формат лога без
`$args`). Утёк — «Сменить токен эндпоинта» на странице расхода или
`ROTATE_TOKEN=1 php -f cli/setup.php`.

**Проверка:** все строки отчёта — OK, `engine audio` и `engine text` —
`registered` (повторно — `unchanged`);

```sql
SELECT ID, CODE, CATEGORY, COMPLETIONS_URL FROM b_ai_engine WHERE CODE LIKE 'sheftoolsai%';
```

Если вернулось `ENGINE_REGISTER_ERROR_COMPLETIONS_URL_FAIL` — портал не
достучался до эндпоинта сам до себя (DNS внутри сервера, самоподписанный
сертификат, закрытый порт). Проверь `curl` **с сервера портала**.

## Шаг 4. Настройки автозапуска по воронкам

**Делать руками, даже если совпадает с дефолтом.** Явно сохранённая
настройка перестаёт зависеть от зоны лицензии — а именно из-за неё вне `ru`
в дефолте нет `Transcribe` (`callchannelsettings.php:112-140`).

В интерфейсе: карточка сделки → настройки Копилота → автозапуск. Для
**каждой воронки**: опция хранится отдельно
(`crm::ai_autostart_settings_<typeId>_<catId>`).

Обязательно включи:
- операцию «распознавание записи» (без неё цепочка не стартует);
- нужные направления (по умолчанию только входящие).

**Проверка:** `cli/ai-call-autostart-diag.php`, раздел 3 — у каждой воронки
`есть Transcribe?` = `OK`.

## Шаг 5. Прогон на заглушке

Провайдер по умолчанию — заглушка (`DEF_provideraudio = echo`), денег не
тратит. Сделай тестовый звонок с записью на сделку или лид (**не на
контакт** — `TargetResolver` берёт только Deal и Lead).

Требования к записи: 60 КБ…25 МБ, 10 сек…60 мин, расширение из
`mp3|mp4|m4a|vp6|aac|wav`.

Что должно произойти:

1. в `crm-ai.log` — `Trying to autostart operation...`;
2. в таймлайне сделки — текст `[заглушка shef.toolsai] Расшифровка записи…`;
3. на странице «ИИ: расход и остаток» — строка `audio/echo/SUCCESS`.

Если встало — `ACTIVITY_ID=<id> php -f cli/ai-call-autostart-diag.php`
покажет, на каком гейте.

**Типичная засада:** транскрипт не появился, ошибок нет. Смотри внешний
адрес и `ai::public_url` — колбэк ушёл на внутренний адрес. В логе проблем
shef.problems (тип «Продажи и CRM») будет «Колбэк не принят порталом».

## Шаг 6. Реальный провайдер

Только теперь. Вкладка **Провайдер**:

| настройка | пример |
|---|---|
| Адрес API | `https://api.openai.com/v1` или свой сервер: `http://whisper.local:8000/v1` |
| Ключ API | `sk-…`; своему серверу без ключа — пусто |
| Модель распознавания | `whisper-1` (у faster-whisper-server — имя модели сервера) |
| Модель текста | `gpt-4o-mini` |
| Цены | минута распознавания, миллион входных/выходных токенов — в валюте квоты |

Затем вкладка **Движок**: «Распознавание речи» и «Текст» — «OpenAI-совместимое
API». Перерегистрировать движки не нужно: провайдер выбирается при каждом
запросе.

Поставь квоту — теперь она защищает деньги: **Движок → Месячная квота**,
например `500`.

**Проверка:** тестовый звонок даёт настоящий транскрипт; на странице расхода
строка `audio/openai/SUCCESS` с секундами и стоимостью.

## Шаг 8. Наблюдение первую неделю

Каждый день — страница «ИИ: расход и остаток»:
- **расход за месяц** — поделить на прошедшие дни, умножить на 30, сравнить
  с бюджетом;
- **ошибки** в последних запросах — если много, разбираться до того, как
  расширять охват.

Не включай сразу все сценарии Копилота: `FULL` — это ×5 запросов на звонок
(`callautostartstrategy.php:241-251`). Начни с одного.

## После каждого обновления Битрикс24

Коротко (подробно — [03-upgrade-watch.md](03-upgrade-watch.md)):

```bash
cd /home/bitrix/www/bitrix/modules/shef.toolsai/cli
# до обновления
/usr/bin/php -f core-api-guard.php > /tmp/guard-before.txt
# после
/usr/bin/php -f core-api-guard.php > /tmp/guard-after.txt
diff /tmp/guard-before.txt /tmp/guard-after.txt
/usr/bin/php -f ai-call-autostart-diag.php
/usr/bin/php -f setup.php
```

`setup.php` вернёт `AI_IGNORE_BAAS`, если обновление `crm` его сбросило, и
перерегистрирует движок, если поменялся адрес.

## Откат

Быстро вернуть как было, не удаляя модуль:

```php
(new \Shef\ToolsAi\Engine\Registrar())->unregister('audio');
(new \Shef\ToolsAi\Engine\Registrar())->unregister('text');
\Bitrix\Crm\Integration\AI\BaasManager::setIgnored(false);
```

Без движков Копилот не найдёт `audio`/`text` и просто не запустится.

Удаление модуля снимает движки, агент и заглушки, а обход BaaS — только если
его включал модуль. Журнал расхода и настройки уходят вместе с модулем; чтобы
оставить — удалять с `savedata = Y` (формы у модуля нет — из кода:
`(new shef_toolsai())->UnInstallDB(['savedata' => 'Y'])` после
`UnInstallFiles()` и `UnInstallEngine()`).
