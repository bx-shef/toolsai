# Runbook: как включить на коробке

По шагам, в этом порядке. Каждый шаг проверяемый — не переходи дальше, пока
текущий не даёт ожидаемого результата. Пути ниже — для BitrixVM
(`/home/bitrix/www`); модуль стоит в `bitrix/modules/shef.toolsai`
(или `local/modules/shef.toolsai` — работает и там).

---

## Шаг 0. Разведка (до включения)

Боевое включение с одним тестовым звонком и откатом — готовый промпт
[prod-check.md](prod-check.md).

```bash
cd /home/bitrix/www/bitrix/modules/shef.toolsai/cli
/usr/bin/php -f preflight.php            # только чтение: сеть, адрес, провайдер, движки
/usr/bin/php -f ai-call-autostart-diag.php
/usr/bin/php -f ai-limits-report.php
/usr/bin/php -f core-api-guard.php
```

`cli/` едет вместе с модулем; если модуль ещё не поставлен — возьми каталог
из архива и укажи корень явно: `DOCUMENT_ROOT=/home/bitrix/www php -f …`.

Выпиши себе три вещи:

| Что | Где смотреть | Зачем |
|---|---|---|
| зона лицензии | первая строка диагностики | не `ru` -> в дефолте автозапуска нет `Transcribe` |
| модуль `bitrix24` | отчёт по лимитам | есть -> включится промо-лимит 5/сутки |
| `ai::public_url` | сторож, раздел «Настройки» | от него зависят колбэк И загрузка записи |

## Шаг 1. Включить лог (первым делом)

Без него все отказы автозапуска уходят в `NullLogger`
(`crm/lib/Service/Logger/LoggerFactory.php:22-24`) и отлаживать придётся вслепую.

В `/home/bitrix/www/bitrix/.settings_extra.php`:

```php
<?php
return [
	'loggers' => [
		'value' => [
			'crm.Integration.AI' => [
				'className' => '\\Bitrix\\Main\\Diag\\FileLogger',
				'constructorParams' => ['/home/bitrix/sh_log/crm-ai.log'],
				'level' => \Psr\Log\LogLevel::DEBUG,
			],
		],
		'readonly' => false,
	],
];
```

Лог — вне корня сайта, как у shef.problems: каталог `/home/bitrix/sh_log`
веб-сервер не отдаёт. Он должен существовать и быть доступен на запись.

**Проверка:** тестовый звонок — в логе строки от `AutoLauncher`.

## Шаг 2. Модуль

Нужны `shef.options` 3.0.0+ и `shef.problems` 2.0.0+ — установщик проверит
и откажется ставиться без них.

1. Файлы модулей — Composer'ом, линейка целиком ([composer.md](composer.md)),
   или архивом: распаковать `shef.toolsai.zip` в `bitrix/modules/`.
2. Поставить: **Настройки → Модули → [SH] ИИ-инструменты → Установить**.
   Установщик создаст таблицы, запишет заглушки эндпоинта и страницы
   расхода и сгенерирует токен. **Портал установка не меняет**: обход
   BaaS, движки и агент включаются на шаге 3 кнопкой «Проверить и
   включить» (решение владельца — установка и включение раздельны).

**Проверка:** в отчёте установки `token` и обе `page …` — ✔, других строк
нет.

## Шаг 3. Внешний адрес и движки

1. **Настройки модуля → Движок → «Внешний адрес портала»**: адрес, по
   которому портал доступен **с самого себя и снаружи**, например
   `https://crm.example.by`. Пусто — берётся `ai::public_url`.
2. **Сервисы → ИИ: расход и остаток → «Проверить и включить»** (или
   `php -f cli/setup.php`, можно сразу с `PUBLIC_URL=https://crm.example.by`).
3. **Настройки модуля → Движок → «Выбрать движок модуля».** CRM берёт
   движок **строго по коду из настройки ИИ портала** (гейт 10 в
   [00-research.md](00-research.md)): зарегистрированный, но не выбранный
   движок не работает. Ссылки «оба / только текст / только распознавание»
   записывают выбранное в настройки ИИ портала (на коробке —
   `/configs/?page=ai`; адрес `/settings/configs/` — облачный), заменив прежний
   выбор этой категории, — поэтому только администратором и только
   отсюда: установщик туда не пишет, «Проверить и включить» выбор только
   показывает. Сценарий «распознавание штатное (`BitrixAudio`), текст —
   модуль» — «только текст»: штатное распознавание не тронется.

Регистрация движка делает GET на эндпоинт и требует ровно 200. Проверить
руками:

```bash
curl -i https://crm.example.by/bitrix/tools/shef_toolsai_completions.php
# HTTP/1.1 200 и {"status":"ok"}
```

Токен эндпоинта едет в адресе и попадает в access-лог веб-сервера. Не
логируйте query-строку для `/bitrix/tools/shef_toolsai_completions.php`
(в nginx — отдельный `location` с `access_log off` или свой формат лога без
`$args`). Утёк — «Сменить токен эндпоинта» на странице расхода или
`ROTATE_TOKEN=1 php -f cli/setup.php`.

**Проверка:** после пункта 3 все строки отчёта «Проверить и включить» —
OK: `engine audio` и `engine text` — `registered` (повторно — `unchanged`),
`selected audio` и `selected text` — «выбран движок модуля «Shef ToolsAI — …»
(sheftoolsai_…)». До пункта 3 `selected …` — FAIL «не выбран» или «выбран
«X»», это ожидаемо. Одна категория на движке модуля, другая на штатном
(«только текст» при `BitrixAudio`) — обе OK: «выбран штатный «X» — эту
категорию модуль не обслуживает». Строки INFO — другие сценарии CRM со
своим выбором движка (оценка звонка по скрипту, повторные продажи,
автоматические дела и антиспам): модуль их не выбирает, только показывает,
что там стоит.

Нужны **оба движка**: audio-движок виден CRM, лишь пока есть text-движок
(`ThirdParty::hasQuality()`, гейт 11), и «Выбрать движок модуля» без
зарегистрированного text ничего не выбирает. Проверить регистрацию:

```sql
SELECT ID, CODE, CATEGORY, COMPLETIONS_URL FROM b_ai_engine WHERE CODE LIKE 'sheftoolsai%';
```

Если вернулось `ENGINE_REGISTER_ERROR_COMPLETIONS_URL_FAIL` («должен быть
валидный URL и отвечать статусом 200») — портал не достучался до эндпоинта
сам до себя (DNS внутри сервера, самоподписанный сертификат, закрытый порт).
Проверь `curl` **с сервера портала**. И проверь, во что внешний адрес
резолвится **на сервере**: ядро ai ходит на адрес движка только по
публичному IP (`setPrivateIp(false)`, [01-engine-contract.md](01-engine-contract.md),
«Требования к сети»). Адрес, который внутри резолвится в `10.*`, `172.16-31.*`,
`192.168.*`, — отказ; отчёт «Проверить и включить» это называет.

Внешний адрес — только со схемой: `https://crm.example.by`, не
`crm.example.by`. Без схемы отчёт скажет «не разобран».

## Шаг 4. Настройки автозапуска по воронкам

**Делать руками, даже если совпадает с дефолтом.** Явно сохранённая
настройка перестаёт зависеть от зоны лицензии — а именно из-за неё вне `ru`
в дефолте нет `Transcribe` (`callchannelsettings.php:112-140`).

В интерфейсе: карточка сделки → настройки Копилота → автозапуск. Для
**каждой воронки**: опция хранится отдельно
(`crm::ai_autostart_settings_<typeId>_<catId>`).

Обязательно включи:
- операцию «распознавание записи» (без неё цепочка не стартует);
- нужные направления (по умолчанию только входящие).

**Проверка:** `cli/ai-call-autostart-diag.php`, раздел 3 — у каждой воронки
`есть Transcribe?` = `OK`.

## Шаг 5. Прогон на заглушке

Провайдер по умолчанию — заглушка (`DEF_provideraudio = echo`), денег не
тратит. Сделай тестовый звонок с записью на сделку или лид (**не на
контакт** — `TargetResolver` берёт только Deal и Lead). Ответственный за
сделку или лид должен иметь право **изменять** дело звонка (гейт 12).

**Каждый тест — новый звонок.** На одно дело ядро ставит задание
распознавания один раз: любое прежнее задание, даже упавшее, глушит
автозапуск при обновлении дела, а ретрай — ровно один (гейт 13). Упал звонок
на заглушке из-за настройки — повторная `attachRecord` на тот же звонок его
уже не запустит.

Требования к записи: 60 КБ…25 МБ, 10 сек…60 мин, расширение из
`mp3|mp4|m4a|vp6|aac|wav`.

Что должно произойти:

1. в `crm-ai.log` — `Trying to autostart operation...`;
2. в таймлайне сделки — текст `[заглушка shef.toolsai] Расшифровка записи…`;
3. на странице «ИИ: расход и остаток» — строка `audio/echo/SUCCESS`.

Если встало — `ACTIVITY_ID=<id> php -f cli/ai-call-autostart-diag.php`
покажет, на каком гейте.

**Типичная засада:** транскрипт не появился, ошибок нет. Смотри внешний
адрес и `ai::public_url` — колбэк ушёл на внутренний адрес. В логе проблем
shef.problems (тип «Продажи и CRM») будет «Колбэк не принят порталом».

## Шаг 6. Реальный провайдер

Только теперь. Вкладка **Провайдер**:

| настройка | пример |
|---|---|
| Адрес API | `https://api.openai.com/v1`, `https://api.deepseek.com/v1` или свой сервер: `http://whisper.local:8000/v1` |
| Ключ API | `sk-…`; своему серверу без ключа — пусто |
| Модель распознавания | `whisper-1` (у faster-whisper-server — имя модели сервера) |
| Модель текста | `gpt-4o-mini`; у DeepSeek — по его странице моделей (например `deepseek-flash`) (распознавания у DeepSeek нет — audio держите на другом провайдере или штатном движке) |
| Цены | минута распознавания, миллион входных/выходных токенов — в валюте квоты |
| Свои промпты для резюме, полей, оценки и дел после разговора | **включить**, если «Текст» — на настоящем провайдере: промпты Копилота на коробке обфусцированы (`ai/install/prompts/world.json`), по ним модель получает текст звонка без инструкции (bx-shef/toolsai#20). По умолчанию выключено |
| Доп. параметры модели текста | JSON-объект в запрос как есть: выключить рассуждения (оплачиваются как выходные токены) — у DeepSeek, например, `{"thinking":{"type":"disabled"}}`, у OpenAI `{"reasoning_effort":"low"}`; имя параметра — по документации провайдера. `max_tokens` здесь задаёт и потолок ответа оценки звонка (умолчание модуля — 8192; выше потолка модели провайдер отвечает 400) |

Таблица выше — **общие** настройки: ими пользуются все направления, у
которых своё не задано. Так работают установки до 1.5.0 — без правки.

### Своя точка доступа у направления (с 1.5.0)

На той же вкладке у каждого направления — свои адрес, ключ и таймаут:

| направление | настройки | пусто — берётся |
|---|---|---|
| Распознавание (audio) | `API_asrbaseurl`, `API_asrapikey`, `API_asrtimeout`; модель `API_asrmodel`, цена минуты `API_asrprice` | общие `API_baseurl`, `API_apikey`, `API_timeout` |
| Текст Копилота (text) | `API_llmbaseurl`, `API_llmapikey`, `API_llmtimeout`; модель `API_llmmodel`, цены `API_llmpricein`/`API_llmpriceout` | общие |
| Анализ сделок | `API_dealbaseurl`, `API_dealapikey`, `API_dealtimeout`, `API_dealmodel`, `API_dealpricein`, `API_dealpriceout` | как у текста (у текста пусто — общие) |

**Ключ откатывается только вместе с адресом.** Задали направлению свой
адрес и не задали ключ — запрос уходит **без** `Authorization`, общий ключ
на чужой сервер не едет. Свой адрес совпал с общим (или с адресом текста
для сделок) — ключ берётся оттуда.

Куда сейчас смотрит каждое направление — на вкладке под заголовком
направления и на странице «ИИ: расход и остаток», блок «Куда уходят
запросы» (адрес, модель, есть ли ключ, таймаут; сам ключ не показывается).
`cli/preflight.php` проверяет `GET …/models` для каждой разной точки.

**Пример: распознавание — свой whisper в Docker, текст и сделки — DeepSeek.**

1. На **том же сервере, где веб-сервер портала** (запрос к провайдеру шлёт
   PHP портала, `127.0.0.1` — это он сам), поднять OpenAI-совместимый
   сервер faster-whisper с `/v1/audio/transcriptions` и ответом
   `verbose_json` (по нему считаются секунды). Например, speaches
   (бывший faster-whisper-server) — образ, тег и имя модели сверить с его
   документацией:

   ```bash
   docker run -d --name whisper --restart unless-stopped \
     -p 127.0.0.1:8000:8000 ghcr.io/speaches-ai/speaches:latest-cpu
   curl -s http://127.0.0.1:8000/v1/models   # сервер отвечает
   ```

   Порт публикуйте на `127.0.0.1`, а не на все интерфейсы: без ключа
   сервер распознает что угодно для кого угодно.

2. Вкладка **Провайдер**:

   | настройка | значение |
   |---|---|
   | Общий адрес API / ключ | оставить как есть или пусто |
   | Адрес API распознавания | `http://127.0.0.1:8000/v1` |
   | Ключ API распознавания | пусто (или ключ, если сервер его требует) |
   | Таймаут распознавания | `600` — на CPU часовая запись распознаётся минуты |
   | Модель распознавания | имя модели сервера, например `Systran/faster-whisper-small` |
   | Цена минуты распознавания | `0` — свой сервер |
   | Адрес API текста | `https://api.deepseek.com/v1` |
   | Ключ API текста | `sk-…` DeepSeek |
   | Модель текста | по странице моделей DeepSeek |
   | Цены 1 млн токенов | пиковые цены DeepSeek |
   | Анализ сделок | пусто — пойдёт туда же, куда текст |

3. Вкладка **Движок**: «Распознавание речи» и «Текст» — «OpenAI-совместимое
   API». «Проверить и включить» не нужно — точка доступа выбирается при
   каждом запросе.

4. **Проверка:** `php -f cli/preflight.php` — в разделе 2 строки
   `API audio`, `API text`, `API deal` с нужными адресами, в разделе 4 —
   `GET http://127.0.0.1:8000/v1/models (audio)` 200 (или 404 — сервер без
   `/models`), `GET https://api.deepseek.com/v1/models (text)` 200. Тестовый
   звонок: `audio/openai/SUCCESS` с секундами и стоимостью 0, затем
   `text/openai/SUCCESS`.

**Адреса во внутренней сети.** POST к провайдеру модуль шлёт с
разрешёнными приватными адресами (`Http\BitrixTransport::post()`, так с
1.0.0): адрес задаёт администратор, и свой сервер в своей сети — законный
случай. Цена этого: тот, кто может менять настройки модуля (администратор
портала), может направить запросы — запись звонка, текст разговора и ключ
направления — на любой внутренний адрес, а до 300 символов ответа попадут в
текст ошибки в журнале расхода. Это уровень доступа администратора, и
отдельной защиты модуль от него не ставит. Адреса из запроса ядра (запись
звонка, колбэк) проверяются, как и раньше.

Цена — одна на вход и одна на выход. У провайдеров с ценой по времени суток
и скидкой на кеш (DeepSeek) ставьте **пиковую цену без кеша** — худший
случай: квота тогда кончится не раньше, чем деньги.

Провайдер без `response_format: json_schema` (DeepSeek понимает только
`json_object`) — анализ сделок всё равно работает: модуль после отказа
повторяет запрос с `json_object` и сверяет ответ со схемой сам. Заполнение
полей при своих промптах просит `json_object`; провайдер без него — один
повтор без `response_format`.

Модуль обслуживает резюме звонка, заполнение полей и оценку звонка по
скрипту. Критерии оценки — из скрипта речевой аналитики CRM (маркер
`criteria`, ядро присылает их само). Повторные продажи — промптом ядра на том
движке, что выбран для них в настройках ИИ; держите их на штатном.

**Дела после разговора на движке модуля** (с 1.3.0, нужны «Свои промпты»).
Настройки ИИ портала (на коробке — `/configs/?page=ai`), группа CRM:
«Копилот создаст дело для менеджера после разговора с клиентом…» — включено,
и в поле «Выберите модель AI для автоматических дел и антиспама»
(`crm_copilot_analyze_communication_engine_code`) — движок модуля
(«Текст»). Вернуть — выбрать там же BitrixGPT. Касается звонков и чатов
открытых линий. **Проверка:** после звонка в журнале расхода
`text/openai/SUCCESS`, в карточке — дела цвета Копилота со сроками; спам и
«ошиблись номером» — дело-исключение с причиной.

Затем вкладка **Движок**: «Распознавание речи» и «Текст» — «OpenAI-совместимое
API». Перерегистрировать движки не нужно: провайдер выбирается при каждом
запросе.

Поставь квоту — теперь она защищает деньги: **Движок → Месячная квота**,
например `500`.

**Проверка:** тестовый звонок даёт настоящий транскрипт; на странице расхода
строка `audio/openai/SUCCESS` с секундами и стоимостью. С текстом на
настоящем провайдере — ещё две `text/openai/SUCCESS` (резюме и поля); в
карточке резюме по делу, поля заполнены или ушли в комментарий;
`cli/call-report.php` — у FillFields в очереди CRM нет `PAYLOAD_IS_EMPTY`.

CRM, модуль — движок текста):

1. Настройки ИИ портала (`/configs/?page=ai`), группа «CoPilot в CRM»:
   включить «…для резюме разговора» (`crm_copilot_summarize_enabled`), «…для
   заполнения полей в CRM» (`crm_copilot_fill_item_from_call_enabled`), при
   желании «…для автоматических дел и антиспама»
   (`crm_copilot_analyze_communication_enabled`). Модель текста —
   движок модуля: ссылка «Выбрать движок модуля: только текст» на вкладке
   «Движок» настроек модуля; модель для дел — отдельный список там же в
   настройках ИИ.
2. Автообработка: «Проверить и включить» модуля включает обход BaaS
   (`crm::AI_IGNORE_BAAS`); опция `crm::AI_CALL_PROCESSING_ALLOWED_AUTO_V2`
   по умолчанию берёт то же значение — если её сохраняли выключенной,
   автозапуска не будет (`cli/ai-call-autostart-diag.php` её показывает).
3. Для **каждой воронки**: карточка сделки → кнопка настроек → «Копилот в
   CRM» → «Автоматическая расшифровка в чатах» → «Только первый чат с
   клиентом» или «Все чаты с клиентом». В зоне `ru` по умолчанию — только
   первый; вне `ru` — выключено. Хранится в
   `crm::ai_autostart_settings_<тип>_<воронка>` (канал `chat`).
4. Вкладка «Провайдер» модуля: «Свои промпты» — тогда модель узнаёт, что это
   переписка, и не считает автоответы бота словами менеджера.

Запуск — при **закрытии диалога**, и только если переписки **не меньше 1000
символов** (`OpenLine::CHAT_MESSAGE_COPILOT_PROCESSING_LIMIT`); короткие
чаты Копилот пропускает молча. Вручную — меню Копилота в деле чата в
таймлайне.

**Проверка:** закрыть тестовый диалог на 1000+ символов, привязанный к сделке
→ в деле чата резюме; на странице «ИИ: расход и остаток» — `text/…/SUCCESS`.

**Оценка переписки по скрипту** (делает модуль):

1. В CRM должен быть скрипт речевой аналитики с выделенной «сутью»
   (критериями). Свой скрипт для чатов — завести и **выключить** (чтобы CRM
   не подобрала его звонкам), его ID — в «Скрипт для чатов» на вкладке
   «Чаты». Пусто — скрипт подбирается, как звонку.
2. Вкладка «Чаты»: «Оценивать чаты по скрипту», лимит за прогон 5–10, окно
   3 дня. Затем «Проверить и включить» — регистрирует агента и создаёт
   таблицу.
3. Прогон руками с отчётом:

   ```bash
   php -f cli/chat-assessment.php
   ACTIVITIES=101 php -f cli/chat-assessment.php
   ```

**Проверка:** в таймлайне сделки комментарий «Оценка переписки по скрипту
«…»: N%»; на «ИИ: расход и остаток» — строка `chat/…/SUCCESS`; на «ИИ:
статистика» — блок «Оценки чатов по менеджерам». Включение пишет комментарии
в CRM клиента — решение владельца портала.

## Шаг 8. Наблюдение первую неделю

Каждый день — страница «ИИ: расход и остаток»:
- **расход за месяц** — поделить на прошедшие дни, умножить на 30, сравнить

  расширять охват.

Не включай сразу все сценарии Копилота: `FULL` — это ×5 запросов на звонок
(`callautostartstrategy.php:241-251`). Начни с одного.

## После каждого обновления Битрикс24

Коротко (подробно — [03-upgrade-watch.md](03-upgrade-watch.md)):

```bash
cd /home/bitrix/www/bitrix/modules/shef.toolsai/cli
# до обновления
/usr/bin/php -f core-api-guard.php > /tmp/guard-before.txt
# после
/usr/bin/php -f core-api-guard.php > /tmp/guard-after.txt
diff /tmp/guard-before.txt /tmp/guard-after.txt
/usr/bin/php -f ai-call-autostart-diag.php
/usr/bin/php -f setup.php
```

`setup.php` вернёт `AI_IGNORE_BAAS`, если обновление `crm` его сбросило, и
перерегистрирует движок, если поменялся адрес.

## Откат

Быстро вернуть как было, не удаляя модуль:

```php
(new \Shef\ToolsAi\Engine\Registrar())->unregister('audio');
(new \Shef\ToolsAi\Engine\Registrar())->unregister('text');
\Bitrix\Crm\Integration\AI\BaasManager::setIgnored(false);
```

Без движков Копилот не найдёт `audio`/`text` и просто не запустится.

Удаление модуля снимает движки, агент и заглушки, а обход BaaS — только если
его включал модуль. Журнал расхода и настройки уходят вместе с модулем; чтобы
оставить — удалять с `savedata = Y` (формы у модуля нет — из кода:
`(new shef_toolsai())->UnInstallDB(['savedata' => 'Y'])` после
`UnInstallFiles()` и `UnInstallEngine()`).
