# Проверка на портале

Всё, что ниже рантайма Битрикса, тестами не закрыть: установка, регистрация
движка, автозапуск распознавания, колбэк, права, удаление. Проверять это
приходится руками — и лучше по списку, потому что забытый шаг находит не
разработчик, а клиент.

Процедура рассчитана на **отдельный стенд**, а не на боевой портал. Шаги
«удалить модуль» на рабочем портале делать нельзя. Готовый стенд в Docker и
промпт, по которому эту процедуру проходит ИИ-агент, —
[agent-docker-test.md](agent-docker-test.md). Включение на боевом портале —
[04-runbook.md](04-runbook.md).

## Что понадобится

| | |
|---|---|
| портал | «коробка» Битрикс24 с модулями `ai`, `crm`, `voximplant`, `rest`; главный модуль **22.600.300** и выше |
| PHP | **8.2** и выше, расширения `mbstring`, `json` |
| кодировка | **только UTF-8** |
| `shef.options` | **3.0.0** и выше |
| `shef.problems` | **2.0.0** и выше |
| доступ | администратор портала и ssh |
| архив | со страницы релиза либо собранный `./build.sh` |

## 0. Архив — тот самый

```bash
git clone https://github.com/bx-shef/toolsai.git
cd toolsai && git checkout <тег проверяемой версии>
./build.sh                       # последняя строка напечатает sha256
sha256sum /путь/к/скачанному/shef.toolsai.zip
unzip -Z1 shef.toolsai.zip | cut -d/ -f1 | sort -u   # ровно shef.toolsai
```

## A. Установка

1. Без `shef.problems` установщик отказывает формой с текстом, а не белой
   страницей.
2. С линейкой — ставится; в отчёте на экране: ✔ `token`, обе `page …` —
   и только они. Портал не изменён: `crm::AI_IGNORE_BAAS` прежний, движков
   и агента нет — их включает «Проверить и включить» (шаг B).
3. `/bitrix/tools/shef_toolsai_completions.php` и
   `/bitrix/admin/shef_toolsai_quota.php` — заглушки в одну строку с путём в
   каталог модуля.
4. Страница настроек открывается, вкладки «Движок», «Провайдер», «Анализ
   сделок»; значение сохраняется.

## B. Движки

1. Задать внешний адрес → «Проверить и включить» → `engine audio`,
   `engine text` — `registered`; повторно — `unchanged`; `selected audio`,
   `selected text` — FAIL с тем, что выбрано сейчас (записать): прогон в
   настройки ИИ не пишет.
2. Настройки модуля → «Движок» → «Выбрать движок модуля» → «Готово», в
   строке и в `/configs/?page=ai` — `sheftoolsai_audio` и
   `sheftoolsai_text`; «Проверить и включить» — `selected …` «выбран наш».
   Не администратором и без `sessid` в ссылке — ничего не меняется.
3. `SELECT CODE, CATEGORY, COMPLETIONS_URL FROM b_ai_engine WHERE CODE LIKE 'sheftoolsai%'`
   — две строки, адрес с `?token=`.
4. `cli/core-api-guard.php` — без FAIL, кроме ожидаемых на этом стенде (записать).

## C. Контракт эндпоинта

| запрос | ожидается |
|---|---|
| GET | 200 `{"status":"ok"}` |
| POST без токена / с чужим | 403 |
| POST с колбэком на чужой хост | 400 |
| POST без `hash` в колбэке | 400 `no_hash` |
| POST с `prompt.file` на внутренний адрес (не портал) | 202, затем `ERROR` / `file_download`, провайдер не вызван |
| POST корректный | **202**, время ответа < 1 с |

Время ответа — главное на apache + mod_php (BitrixVM): там нет
`fastcgi_finish_request()`, и если соединение держится до конца обработки,
ядро снимет задание по таймауту 5 секунд.

## D. Звонок → транскрипт (заглушка)

Настройки автозапуска по воронке сохранены явно, соглашение Копилота принято
ответственным. Входящий звонок с записью (10+ секунд, 60+ КБ) на лид и на
сделку:

- в таймлайне — `[заглушка shef.toolsai] Расшифровка записи…`;
- на странице расхода — `audio/echo/SUCCESS`;
- `shef_toolsai_usage` — строка с `JOB_HASH`.

## E. Провайдер

OpenAI-совместимое API (стенд: `docker/mock-openai`; боевой — ваш):

- транскрипт от провайдера в таймлайне, расход в секундах и деньгах;
- неверный ключ — `ERROR` / `provider_auth`, ключа в тексте ошибки нет;
- провайдер недоступен — `provider_unavailable`, эндпоинт всё равно 202.

## F. Квота

- квота на микро-единицу — `QUOTA_EXCEEDED`, провайдер не вызван;
- 0 — безлимит;
- повтор задания с тем же `hash` — провайдер не вызван, строка одна.

## G. Анализ сделок

- `cli/deal-health.php` по сделке без дел 20 дней — риск ≥ порога,
  комментарий в таймлайне, дело старшему;
- повтор сразу — без второй эскалации;
- свежая сделка — «в работе», модель не вызвана;
- агент в `b_agent` один, после него текущий пользователь прежний.

## G2. Токен

- «Сменить токен эндпоинта» — движки `updated`, старый токен — 403, новый
  работает.

## H. Удаление

- при стоящем `shef.toolsai` удаление `shef.problems` отказывает;
- после удаления: движков, агента, заглушек, таблиц `shef_toolsai_*` и
  настроек нет; `crm::AI_IGNORE_BAAS` вернулся, если его включал модуль;
- чужой файл на месте заглушки не тронут ни установкой, ни удалением.
