# Приёмка shef.toolsai на коробке в Docker — 2026-10-02

Стенд: main 26.750.0, ai 26.1100.0, crm 26.800.0, voximplant 26.700.0,
PHP 8.2.33, MySQL (Percona) 8.0.46, зона ru (пробная лицензия), модуль bitrix24: нет.
Модули: shef.options 3.0.15 (88571d1), shef.problems 2.0.0 (8608718), shef.toolsai 1.0.1 (28807fa) + правка ниже.

Ход приёмки по шагам — [issue #3](https://github.com/bx-shef/toolsai/issues/3).

**Отличие стенда от промпта.** Коробка уже стояла в официальном env-docker
(nginx + php-fpm), а не в `docker/` (apache + mod_php). Из `docker/` взяты
`mock-openai`, `configure.php`, `webhook.php`, `test-call.sh` (с `curl -k` и
уникальным именем записи). Проверка «POST 202 < 1 с на mod_php» здесь **не
покрыта** — на fpm 202 отдаётся за ~0.009 с.

Ядро запрещает приватный адрес движка (находка 1), поэтому `nginx` подключён к
docker-сети `198.18.0.0/24` (RFC 2544 — PHP считает её публичной) с алиасом
`b24portal`; внешний адрес модуля и `ai::public_url` = `http://b24portal`.
Наружу ничего не открывалось.

## Итог

Работает с оговорками: главный путь «звонок → транскрипт в карточке» проходит
на заглушке и на OpenAI-совместимом провайдере, квота и ошибки провайдера — по
контракту; но эскалация анализа сделок падала на crm 26.800 (исправлено одной
строкой), ротация токена и смена адреса не работают из-за кеша ядра, а
текстовая цепочка Копилота (резюме, заполнение полей) на коробке не может дать
осмысленный результат — промпты Битрикса обфусцированы.

  уже стоял, установщик сначала отказал по модулю `ai`.

  пользователя не заводил.
- Распознавание настоящей речи — только синус и заготовки mock.
